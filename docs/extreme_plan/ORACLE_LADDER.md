# Oracle Ladder：本地诊断实验说明

## 1. 隔离原则

Oracle Ladder 只允许在本地 `RadioEnv` 上运行，代码中有硬断言：

```python
assert isinstance(env, RadioEnv), "Oracle Ladder只允许在本地RadioEnv上读取真值"
```

官方模拟器只能运行使用 `/enter`、`/measure`、`/clear`、`/exit` 返回信息的合法策略。官方不提供哪些频道有源、精确坐标、真实数量、半径和方向，因此 O0/O1/O2/O3 不能上官方模拟器。

## 2. 五层定义

| 模式 | 偷看的信息 | 正常保留的信息 | 用途 |
| --- | --- | --- | --- |
| G25OR | 无 | 全部正常 | 当前基线 |
| O1 | 有源频道集合 | 位置、半径、方向未知 | 空频道扫描成本 |
| O2 | 首次命中后的精确坐标 | 频道集合仍未知 | 定位成本 |
| O3 | 有源频道 + 首见精确坐标 | 仍需空间发现 | 纯搜索/发现成本 |
| O0 | 数量、频道、精确坐标 | 只保留移动和clear | 物理极限 |

O0 不调用 `/measure`，使用 Held-Karp 开放中心TSP顺序，并在每个源的20m清除圆内做连续优化；Q3/Q4的O0结果应完全一致。

## 5. Sanity check

- N=1时，O0时间严格等于 max(0, |g|-20)/5+5；
- 同一位置、同频道下，全向源和任意定向源的O0时间和距离完全一致；
- 30场景和50场景结果方向一致，全部策略100%清除。

## 6. 结论

Q3和Q4的最大瓶颈都是未知源空间搜索；Q4其次是空频道扫描；定位几何不是最大瓶颈。下一步应优先研究可证明的搜索覆盖、频道账本、发现顺序和路线优化，而不是继续第二测点或G21A零绕行补测。

## 6. 因果拆分（复用同一批50对场景）

在五策略配对之外，新增 A/B/C 三个诊断臂，逐场景恒等式为

    G25OR - O0 = (G25OR - C) + (C - B) + (B - O0)

其中 A = 首次发现全部真实源即停；B = A + 真值最优20 m清除；C = 真值仅用于选择合法覆盖/求解顺序。

| 项目 | Q3 s/源 | Q4 s/源 |
| --- | ---: | ---: |
| A 仅发现 | 130.51 | 329.90 |
| B 发现+真值清除 | 268.85 | 468.18 |
| C 合法路线Oracle | 330.11 | 606.28 |
| 顺序损失 G-C | 1.94 | 7.69 |
| 合法信息/证明 C-B | 61.27 | 138.10 |
| 搜索-清除整合 B-O0 | 126.02 | 323.86 |
| 总差距 G-O0 | 189.22 | 469.65 |

结论：顺序/微顺序损失占总差距仅1.0%/1.6%；最大瓶颈是固定全覆盖路线先发现后清除的串行结构
（B-O0 占66.6%/69.0%）；Q4 的合法信息/空频道证明成本也显著更高。复现与完整表见
`docs/extreme_plan/CAUSAL_DECOMPOSITION.md`，原始数据见
`results/extreme_plan/causal_decomposition_50scenes_*.csv/json`。
