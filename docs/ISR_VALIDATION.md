# ISR 接入验证与官方自动对照实验

## 当前结论

ISR 已接入真实仓库，并保留 S3/S25 覆盖义务、双侧定位、有限中心试清、100 次快速调度预算和原完成证书。Q3、Q4 的服务任务准入半径固定为 800 米和 300 米。本轮没有训练 PPO、调整 S21 或追加 Oracle。

附件的 CSV 汇总和计时恒等式核算一致，但独立模拟核无法在 Windows 上逐局复现：1040 次完整复跑中有 218 次与 Linux 存档不同。根因是双侧定位对两个理论等距的对称探测点使用原始浮点距离排序，Windows 与 Linux 的末位差异会改变访问次序。修复后，已知 Q3 seed 220001 案例在 Windows 和 WSL 上得到完全相同的总时间、测量次数和路程。原附件保持不变，完整差异表保存在 `results/isr_validation/handoff_rerun/`。

## 接口与故障处理

`scripts/run_official_g25o.py` 现在接受 `--variant ISR --coverage S25`。其他覆盖标签会在调用 `/enter` 前拒绝。策略和客户端共享两位小数及 1.01 度保守包络配置。

网络失败、业务拒绝、缺失字段和非有限示向度统一作为 `ActionIOError` 向上传播，G25OR 与 ISR 都不会把它们当成几何失败并转入光学保底。网络重试保持完整请求体和 request ID 不变。runner 即使失败也会在 `summary.json` 写入错误类型、错误信息和 traceback。

Q3/Q4 的 G25OR、ISR 已分别通过串行 mock HTTP 联调。并行访问同一 mock 会话的一次无效测试保留在 `results/isr_validation/http_mock/` 并明确标为无效；有效证据在 `http_mock_serial/`。

## 官方自动演练

自动入口：

```powershell
python scripts\auto_official_isr_experiment.py `
  --out-dir results\isr_validation\official_20260912 `
  --smoke-runs-per-group 3 --main-runs-per-group 100
```

脚本只识别并调用“开始问题3演练测试”或“开始问题4演练测试”，使用 UIA Invoke，不使用坐标点击。它先完成 Q3/Q4 × G25OR/ISR 各 3 局，共 12 局接入验收；全部从官方数据库核对源总数和清除数后，才继续 400 局主实验。

固定调度种子为 20260912。每个区组包含 Q3/Q4 与两个策略各一局，区组内次序随机。每局使用独立目录并立即更新 `progress.json`、`ledger.csv` 和 `attempt.json`。中断后使用同一命令加 `--resume`；代码哈希、提交、队号或配置不一致时拒绝续跑。

任意确认的未全清会立即停止；连续两次技术故障也会停止。所有失败和缺失记录都保留，不能用补跑成功局替换。官方案例不可重放，因此区组只控制批次次序，结果不称为同案例配对。

模拟器需先完成一次登录。登录后，自动程序负责发起演练、等待接口、运行策略、主动退出、返回演练页和继续下一局。正式测试按钮不在允许列表中。

## 官方结果判定

批次完成后运行：

```powershell
python scripts\analyze_official_isr.py results\isr_validation\official_20260912
```

Q3、Q4 分别采用 ISR 的冻结条件为：该题 200 次主实验尝试全部经官方数据库确认全清；ISR 每局 T/N 均值至少降低 3%；10,000 次区组 bootstrap 的均值差 95% 区间上界小于 0；ISR 的 P95 不超过 G25OR 的 103%。任何条件不满足都保留 G25OR。
